# Model-Independent Agent Protocol

Start at project AGENTS.md and .agent/START.md. The project owns current
decisions and task context; generic role packages define how to perform a role.
Use .agent/versions.md for exact sources and snapshots, .agent/assignments.md
for task ownership and .agent/project/ for project-specific role supplements.

## Updates
Inspect the upstream change, propose a deliberate version bump in a separate
reviewable change and retain project supplements. Verify snapshot hashes after
copying. Do not edit vendor files locally as though they were project policy.
Reconcile changes to project rules with active feature branches before adoption.

## Routine Work
Apply relevant current project-MD's for every task. Read changes or missing
context, not every guide in full on every tool call. A new session still reads
the core boundaries, own role, contract and latest verified checkpoint.

Use the project handoff from .agent/DELIVERY.md and the pinned checkpoint
requirements. Keep full logs outside model context where possible, but retain
the actual test evidence and enough context for safe continuation.

## Honest Limits
These are versioned instructions, not a background service, security sandbox,
automatic restart or guaranteed token saving. The existing 64-turn failure
was a runner limit, not proof of a subscription quota. The adoption does not
alter that setting. No new provider, key, account or runtime is activated.

Protocol v0.1.0 remains a pilot until a real authorized build/handoff cycle is
tested. No merge, release or production action follows from reading these files.
